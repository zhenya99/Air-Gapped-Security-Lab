# Required companion change on the existing Proxmox host.
# Do this after the SRX and Cisco changes are validated.
# This is an editing guide, not an executable shell script.

1. Back up /etc/network/interfaces to a new, uniquely named pre-change file.
   Example for the first deployment:
       cp -a /etc/network/interfaces /root/interfaces.pre-dns-lab

2. In the existing vmbr0 stanza, change only:
       bridge-vids 10 99
   to:
       bridge-vids 10 20 99

3. Preserve all other live configuration, especially:
       vmbr0 address 172.16.99.20/24
       vmbr0 gateway 172.16.99.1
       vmbr0 bridge-ports nic0
       vmbr0 bridge-vlan-aware yes
       vmbr1 bridge-ports nic1
       vmbr1 has no IP/gateway, no VLAN filtering/tag applied to sensor net1
       nic1 -> vmbr1 -> VM 900 net1 -> ens19 -> bond0 uses MTU 9000

4. Review the diff and reload networking using the installed ifupdown2 tooling:
       diff -u /root/interfaces.pre-dns-lab /etc/network/interfaces
       ifreload -a
   Have the local console available; a network reload can interrupt access.

5. Verify:
       ip -br addr
       bridge -compressvlans vlan show
       qm config 900
   Confirm VLAN 20 on nic0/vmbr0, management connectivity, and sensor capture.

6. When creating the future VMs:
       VM 910 net0: vmbr0, VLAN tag 10, 172.16.10.50/24
       VM 920 net0: vmbr0, VLAN tag 20, 172.16.20.53/24
   Leave VLAN tags out of the guest interface configuration.
   Keep Security Onion net0 untagged and net1 on vmbr1 untagged.
   Match the baseline's Proxmox firewall setting for these lab NICs (disabled);
   guest firewalls still need DNS and administration rules.

7. No VM creation commands are included because VMIDs must first be checked
   for availability and storage/CPU/memory allocations must be selected.
